Развёртывание Planka через GitHub

Этот гайд базируется на официальной документации Planka и показывает, как хранить инфраструктурные файлы в GitHub, автоматически деплоить их на сервер и сделать сервис общедоступным.

Что понадобится

  1. Аккаунт на GitHub и репозиторий (можно использовать текущий).
  2. Сервер с публичным IP и SSH-доступом.
  3. Установленные Docker и Docker Compose plugin.
  4. Доменное имя, указывающее на сервер (например, planka.example.com).

Структура репозитория

  • planka/docker-compose.yml — оркестрация Planka, PostgreSQL и Caddy.
  • planka/.env.example — шаблон переменных окружения.
  • planka/Caddyfile — базовая конфигурация обратного прокси.
  • .github/workflows/planka-deploy.yml — GitHub Actions для доставки и проверки.
  • .gitignore — исключает приватный файл planka/.env.

Готовим файл .env

  1. Скопируйте planka/.env.example в planka/.env.
  2. Укажите публичный адрес сервиса: BASE_URL (например, https://planka.example.com), домен без протокола для Caddy в PLANKA_DOMAIN и e-mail администратора в PLANKA_TLS_EMAIL.
  3. Заполните секретный ключ, данные администратора и параметры PostgreSQL.
  4. Добавьте SMTP-настройки, если нужна почта, и при необходимости OAuth-провайдеры.
  5. Содержимое файла сохраните в секрете GitHub PLANKA_ENV_FILE.

Секреты GitHub

В разделе Settings → Secrets and variables → Actions добавьте:

  • PLANKA_ENV_FILE — содержимое planka/.env.
  • PLANKA_HOST — адрес сервера.
  • PLANKA_USER — SSH-пользователь.
  • PLANKA_SSH_KEY — приватный SSH-ключ.
  • PLANKA_REMOTE_PATH — путь вроде /opt/planka.
  • PLANKA_PUBLIC_URL — (опционально) публичный URL для автоматической проверки доступности.

Подготовка сервера

curl -fsSL https://get.docker.com | sudo sh
sudo apt-get install -y docker-compose-plugin
sudo usermod -aG docker $USER
sudo mkdir -p /opt/planka
sudo chown $USER:$USER /opt/planka

Откройте во внешнем файрволе/безопасности провайдера порты 80 и 443 — их будет слушать контейнер Caddy, автоматически выпуская сертификаты Let's Encrypt.

Отдельно устанавливать Caddy не нужно: он запускается внутри Docker Compose и проксирует запросы к приложению.

Workflow GitHub Actions

Файл planka-deploy.yml выполняет следующие шаги:

  1. Чекаутит код.
  2. Создаёт planka/.env из секрета.
  3. Отправляет docker-compose.yml, Caddyfile и .env на сервер через scp.
  4. Выполняет docker compose pull, docker compose up -d и выводит статус контейнеров.
  5. При наличии секрета PLANKA_PUBLIC_URL пытается обратиться к сайту из GitHub Actions и завершится ошибкой, если ответ не будет получен.

Запустить его можно вручную или просто сделать commit/push в ветку main. Успешное выполнение заключительного шага подтверждает, что Planka открывается из интернета.

Проксирование через Caddy

Контейнер Caddy запускается автоматически и получает настройки из planka/Caddyfile. Базовая конфигурация использует переменные окружения из .env:

{$PLANKA_DOMAIN} {
  encode gzip
  reverse_proxy planka:1337
  tls {$PLANKA_TLS_EMAIL}
}

Проверяем результат

  1. Запустите workflow «Deploy Planka».
  2. На сервере выполните docker compose ps и docker compose logs -f planka.
  3. С локальной машины проверьте HTTP-ответ: curl -I https://planka.example.com — код 200 или 302 подтвердит доступность.
  4. Откройте https://planka.example.com и войдите под админом.

Если сайт не открывается

  1. Убедитесь, что workflow завершился без ошибок. Если шаг «Check public availability» упал, изучите вывод curl -Iv в логах.
  2. На сервере проверьте контейнеры: docker compose ps, docker compose logs caddy и docker compose logs planka.
  3. Проверьте DNS: dig +short planka.example.com должен возвращать IP вашего сервера.
  4. Разрешите порты 80 и 443 во внешнем файрволе провайдера.

Обновления и безопасность

  • После первого входа смените пароль администратора.
  • Для обновления версии измените тег образа в docker-compose.yml и перезапустите workflow.
  • Проверяйте, что шаг «Check public availability» завершается успешно — это гарантирует доступ к сервису из сети.
  • Делайте резервные копии томов Docker: postgres-data, attachments и других.
